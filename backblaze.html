GPU training pipeline map for Backblaze

Backblaze lists CoreWeave as a free-egress partner, so training reads from B2 into CoreWeave GPUs skip the $0.01/GB overage

Built by Gursimar Singh, Nov 2026

The post says an SE shows where Backblaze slots into a customer's AI pipeline. I mapped a common setup, S3-based training on CoreWeave, from ingest to checkpoints and archive, using only Backblaze's own pages. One thing the math shows: on a cloud that isn't a partner, Overdrive's list price beats standard B2 plus overage once a dataset is read about 3.8 times a month.

Discovery questions

  • Workload: What are you training (modality, model size) and how big is the dataset today and in 12 months?
  • Workload: How many full passes over the data does a run make per month, and how many runs overlap?
  • Compute: Which GPU clouds do you train on now, and which might you add? Is it all CoreWeave?
  • Data path: How do data loaders read today: S3 API, POSIX mount, or a cache tier such as WEKA or local NVMe?
  • Throughput: What aggregate read throughput keeps your GPUs busy, and where do they wait today?
  • Checkpoints: How big is a checkpoint, how often do you write one, and how many do you keep?
  • Recovery: When a run fails, how long does restoring the last checkpoint take, and what does an idle hour of the cluster cost you?
  • Governance: Do weights or datasets need immutability, a second region, or a BAA?
  • Current stack: What storage are you replacing, and what does egress cost you there each month?
  • Migration: How much data has to move in, from where, and by when?
  • Decision: Who signs off on a storage change, and what result in a POC would make it an easy yes?

Example workload (not a customer): 2,000 TB read 4 times a month. To a non-partner cloud: B2 $13,900 storage + $20,000 overage = $33,900, vs Overdrive $30,000. On CoreWeave, B2 egress is $0, so B2 = $13,900. List prices, decimal TB, no commit discounts.

How it works

  • Pull every pricing, egress, throughput and feature claim from backblaze.com (pricing, B2 Overdrive, AI/ML, AI integrations, S3 API docs, the CoreWeave announcement) and keep the exact quote for each, so a script can check it.
  • Draw the data flow: raw data lands in B2, CoreWeave GPUs stream training shards over the S3 API, checkpoints go back to B2, and old checkpoints and final weights are locked and replicated for recovery or a move to another cloud.
  • Turn the open points into discovery questions and POC tests, and compute where egress costs flip from published list prices: 3 + (15 - 6.95) / 10 = 3.81 reads per month.

What I'd improve next: Run the throughput and checkpoint tests on a real CoreWeave node pool with an open dataset, publish the numbers next to these list-price facts, and add a second map for the new path where Backblaze runs HDD tiers inside CoreWeave AI Object Storage, so an SE can tell a customer which one fits their workload.
