3 fixes for Clay's demo path

  1. Make phone optional on step 1. Clay is the only one of the four that requires a phone number before submit; Apollo starts with email alone. Clay can enrich a phone after the meeting is booked.
  2. Don't ask what enrichment can answer, and ask the one thing it can't. Neither step asks company size or CRM, which is fine since Clay can pull both from the domain, but none asks timeline or team size. Unify asks how many sales reps. One "how many reps would use Clay?" question would route seats-level deals faster.
  3. Route on the step-2 answers right away. The role picker and 13 use-case boxes are strong routing inputs. Send RevOps + "Inbound lead orchestration" to a GTM engineer calendar on the thank-you page, and send agency answers to the partner team.

The Clay table below (CSV) is my design for auto-qualifying these leads: inputs from the form, Clay enrichments on the domain, a fit score (my own heuristic) and a route. I only looked at public pages and did not submit any form, so reply timing isn't measured.

How it works

  • Open each company's demo page in a headless Chrome and read every input, select and checkbox, including fields hidden until a later step.
  • Compare fields before submit, required phone, and which questions actually qualify the lead (role, use case, team size, CRM).
  • Turn the gaps into 3 fixes and a Clay table schema that would score and route these leads from the domain alone.

What I'd improve next: Submit test requests from a real work domain with permission, time the confirmation and first human reply for each tool over a week, and test the fit score against which demo requests became opportunities.
